Automatic Testing Platform for Rails, Bun, and .NET

Standardized quality strategy for all products: BDD for backend business rules, Playwright for end to end UI, unified pass/fail summaries in CI, and k6 based load/stress validation.

BDD: Cucumber / SpecFlow Unit/API: RSpec, bun:test, xUnit UI: Playwright Reports: Allure + JUnit XML Perf: k6 + Grafana

1) Chosen Solution by Technology

Project Type Backend BDD Unit/API Tests UI Tests Reporting
Rails cucumber-rails + Gherkin RSpec + request specs Playwright (web UI) RSpec JUnit + Cucumber JSON + Allure
Bun apps cucumber-js bun:test (unit + service tests) Playwright JUnit XML + Allure aggregation
.NET apps SpecFlow (Gherkin) xUnit + WebApplicationFactory Playwright for .NET or Node runner TRX/JUnit + Allure
One Gherkin language across stacks Stack specific runners No custom in house framework needed

2) Test Pyramid and Scope

Unit Layer (fast gate)

Runs on every push. Validates domain logic, transformers, validators, policies.

API/Service Layer

Contract + integration tests for controllers/endpoints. Includes DB and auth scenarios.

BDD Layer

Business workflows in Gherkin. Shared language with product and QA teams.

UI E2E Layer

Playwright smoke and regression packs. Focus on critical user journeys and cross browser checks.

Performance Layer

k6 load and stress profiles. Triggered nightly and before production deployment windows.

4) Load and Stress Architecture

Layer Selected Tool Why
Test execution k6 Developer friendly JS syntax, CI ready, deterministic scenarios
Metrics storage InfluxDB (or Prometheus via remote write) Time series retention and quick querying
Visualization Grafana Latency/error/concurrency dashboards by service
Alerting Grafana Alerting + CI quality gates Automatic fail when SLO thresholds are breached

Recommended policy: every release candidate must pass smoke load profile (p95 latency and error rate) before deployment approval.
